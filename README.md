# 每日签到（Android · 中转站通用版）

我做了这个 Android 签到工具，方便在手机上添加和管理多个网站的签到任务，适合领取积分、额度或类似每日权益的中转站。当前**显示版本 1.0**，`versionCode` 为 **11**；支持 Android 8.0（API 26）及以上，目标 API 34。手机独立运行，不需要 Termux、Python，也不需要复制电脑端 Cookie。

公开发布包只上传手机端 APK、源码和说明；电脑端程序、构建产物、验证日志和签名密钥不随公开包发布。公开发布后也可在 GitHub Releases 的 v1.0 附件下载同一 APK。

## 下载与安装

- 仓库：[HRylink/daily-checkin-android](https://github.com/HRylink/daily-checkin-android)
- 下载：[签到.apk](./签到.apk)；发布后也可从 [Releases](https://github.com/HRylink/daily-checkin-android/releases) 获取。建议核对 `SHA256SUMS.txt`。
- 软件设置页最底部「GitHub 仓库 · 查看源码」可打开上述仓库。
- 将 APK 传到手机后点击安装；按系统提示允许所用文件管理器或浏览器「安装未知应用」。
- **升级请直接覆盖安装，不要先卸载。**官方 APK 与旧版保持同包名、同签名；直接覆盖可保留已保存的账号、加密凭据和领取记录。
- 自己从源码首次构建会生成新的 `debug.keystore`，签名与官方 APK 不同，不能覆盖安装官方包。强行切换签名需要卸载，而卸载会清除本应用的私有数据，详见 [docs/BUILDING.md](docs/BUILDING.md)。
- 禁止应用备份；卸载或「清除应用数据」会删除本机账号、登录态与记录。

## 功能

- 首页点一次圆形「每日签到」按钮，为已添加且开关已启用的网站执行签到或领取；运行中可切到其他应用，但请勿强制停止本应用。
- 设置页用动态账号卡管理各网站，每张卡有名字、余额/最近领取文本、签到开关、删除，以及适用的重新登录或编辑入口。
- 设置页可见时，只对应用已适配的账号静默查询只读余额或积分，每站点至少间隔 30 秒；查询失败保留旧值并标「查询失败」。余额查询不会发起领取，也不会调用自定义站点的领取接口。未适配站点只显示最近一次确认的结果。
- 领取结果写入首页、私有签到记录与通知；底部「签到记录」按日期显示最近 100 条。
- 凭据使用 AndroidKeyStore AES-GCM 加密；自定义站点 POST 未确认结果当天不重放，自定义 GET 仅在瞬态网络异常时最多重试一次。
- **没有后台每日定时签到、开机任务或系统自动重试。**「每日」是按钮名称，实际仍需每天由用户点击启动。

## 添加网站：自动识别与自定义领取接口

- 设置页「+ 添加账号」粘贴中转站网址后，应用会自动识别该网址是否属于已适配平台；匹配到时显示对应登录入口，多匹配时选择候选。
- 自动识别按已知域名匹配，**不会**分析网页、发现签到按钮或推断任意网站的领取接口。识别不到时，「添加该网站」会打开通用配置并预填有效的 https 网址；也可以点对话框底部「自定义站点（通用）」。
- 通用站点需要填写真正的领取接口地址（不是任意网站首页）、GET 或 POST、可选 POST 请求体及必要的非敏感额外请求头。通常要在电脑浏览器登录自己的站点后，用 F12 → Network → Fetch/XHR 观察一次手动领取请求，核对 Request URL、Method、Payload 和 Headers。
- 仅适用于「在应用内 WebView 完成登录后，Cookie 对该领取接口同源有效」的场景；需要动态签名、Bearer 令牌、动态 CSRF、验证码的接口不保证可用。接口只支持 https 与同源 https 重定向，证书错误会停止；Cookie/Authorization 等敏感头不能写进配置。
- 保存配置不调用接口；点「打开登录页」完成登录后，点「我已完成登录」会先加密保存 Cookie，再**立即领取一次以验证凭据，可能就是当天领取**。应用原样显示站点返回文本；HTTP 2xx 表示请求被接受，不等于积分/额度一定到账。401/403 要求重新登录，400/404/5xx 显示站点原话。
- 日常签到调用同一接口。POST 因超时/断连而结果未确认时，当天再次点击、重开页面或进程中断都不重发；GET 的 429、401、403 等 HTTP 错误不重试，瞬态网络异常才最多等待 600ms 重试一次。编辑配置不领取；只有显式「重新登录 / 验证」或一键签到会调用领取接口。
- 配置（名称、网址、方法、请求体、额外头、账号清单、余额缓存与记录）保存在应用私有目录但**不加密**：不要把密码、Cookie、令牌、Authorization 或私密请求体放进去。详细边界见 [使用说明.txt](使用说明.txt)。

## 代理与通知

- 应用没有内置代理，也不会启动代理软件；请求走手机当前系统网络、代理或 VPN。请按网站实际登录域名和领取接口域名设置直连或代理，并确保应用本身没有被代理软件的分流规则排除。
- 不要把电脑上的本地代理地址填成手机代理。使用 VPN/TUN 模式时，需要直连的域名仍应在代理软件中设为 DIRECT。
- 建议允许通知权限，以便看到前台任务的进度、结果和失效提示。Android 13+ 可在设置页底部「通知设置」申请 `POST_NOTIFICATIONS`；已授权或旧版系统打开系统通知设置。拒绝通知仍可启动签到，但要回首页查看结果。
- 域名规则正确也不保证成功：DNS、节点质量、断网切换、站点限流、人机验证与登录授权状态都可能导致失败；应用不承诺永久免登录。

## 隐私

- 密码、会话 Cookie、访问/刷新令牌、设备密钥及自定义站点领取 Cookie 使用手机内不可导出的 AndroidKeyStore 密钥加密；APK 不内置任何真实账号或 Cookie。用户名、站点名称和自定义接口配置仅保存在应用私有目录，不加密，请勿在其中写入敏感信息。
- 应用没有开发者运营的分析/遥测/崩溃上报服务器，也没有第三方广告或统计 SDK；网络请求只发往用户使用的已适配网站、其登录授权地址及用户自行填写的 https 自定义站点。
- **删除依赖 WebView 登录态的账号可能清除本应用 WebView 的全部 Cookie**，从而影响其他站内登录；它不是网站远端退出登录。删除其他账号只清除本机对应凭据/缓存。
- 完整说明见 [docs/PRIVACY.md](docs/PRIVACY.md)。

## 我的测试情况

- 已测：`./test.sh` 包含 12 个手机端套件——网络协议、通用站点、余额、登录、可靠性、运行流程、历史的 JVM/本地 HTTP 夹具测试，以及 Android 静态接线、UI 静态契约。它们覆盖协议状态、令牌刷新、POST 防重放、余额只读汇总、缓存、加密键路径、历史积分迁移和静态源码接线。
- 已测：本次 APK 完成 Java 8/Android 34 编译、4 字节对齐与 v2/v3 签名校验；新增设置页仓库链接不改变签到协议。显示版本仍为 1.0，内部版本码递增为 11。
- 真机测试：我已经将 APK 安装到手机，并连接多个网站成功完成签到领取。它在我测试过的网站上可用，但我不保证所有中转站都兼容。
- 尚未全面覆盖：我还没有逐一验证所有机型的前后台切换、通知权限生命周期、SSO、代理配置和跨版本数据保留；本次新增的仓库链接入口也需要随更新包在手机上进一步核对。
- 自定义 GET 的「一次重试」是应用层预算；`HttpURLConnection` 在服务器完全无响应时可能透明重发 GET，不能保证各平台底层请求总数恰好为两次。POST 在本地夹具中验证断连、无响应、超时均只发送一次。
- 这些静态契约与本地夹具不是设备端、端到端或站点兼容性测试。
