每日签到 APK v1.0（中转站网站签到 · 积分/额度领取）

用途
我做这个工具是为了在手机上添加和管理多个网站的签到任务，适用于支持每日签到或领取积分、额度的中转站。粘贴网址后自动识别已适配平台；其他网站可通过通用接口配置添加。配置完成后，每天点击首页「每日签到」即可执行已启用账号的任务。

重要边界
- 网址自动识别是域名匹配，不会自动解析任意网站的签到按钮、接口或验证方式。
- 未适配网站须自行填写实际领取接口。仅粘贴首页网址不能保证完成配置或签到。
- 本版没有后台每日定时签到、开机任务或系统自动重试，需要用户点击启动。
- 仅用于你自己的账号或已获授权的账号，请遵守网站服务条款和领取规则。

安装与升级
- 安装包：签到.apk；Android 8.0 及以上；不需要 Termux 或在手机安装 Python。
- 下载后允许浏览器/文件管理器安装未知来源应用，点击安装。
- 旧版请直接覆盖安装，不要先卸载。同包名、同签名的升级可保留账号和领取记录；卸载或清除应用数据会删除它们。
- 显示版本 1.0，内部 versionCode 11，包名 com.velpro.checkin。
- 设置页最底部「GitHub 仓库 · 查看源码」打开 https://github.com/HRylink/daily-checkin-android。
- 自行编译的包通常使用不同签名，不能直接覆盖发布包；签名密钥不在公开源码中。

添加网站与账号
1. 首页右上「设置」→「+ 添加账号」。
2. 输入或粘贴网站网址，应用自动识别：匹配到时点「开始登录」，按网页提示完成登录/授权；多个候选时选择对应入口。
3. 识别不到时点「添加该网站」，或点底部「自定义站点（通用）」，填写网站名称及实际领取接口配置。
4. 登录/验证成功后显示账号卡。验证失败时保留待验证账号并显示原因；可重新登录或删除。
5. 账号卡上的「启用签到」开关即时保存。只有已添加且启用的账号参与每日领取；点「删除」后卡片消失。
6. 已适配账号若需要用户名/密码，按卡片表单填写并点「保存设置」。其他账号的网页登录或授权按照对应页面进行。

通用站点配置
- 名称：用于卡片和记录显示。
- 领取接口地址：完整 HTTPS URL，可含路径和查询参数，但不要放密码、Cookie 或令牌。
- 方法：GET 或 POST；POST 请求体可选，按原样发送。
- 额外请求头：每行「名称: 值」，例如 Content-Type: application/json。禁止手填 Cookie、Authorization、Host、Content-Length 等敏感/保留字段。
- 如何找接口：在你自己的站点登录后，用浏览器开发者工具 Network → Fetch/XHR 观察一次手动签到或领取请求，记录 Request URL、Method、Payload 及必要的非敏感 Headers。
- 配置本身不加密，不要把认证数据放在名称、网址、请求体或请求头里。
- 仅适用于 Cookie 登录即可调用的接口；动态签名、Bearer 令牌、动态 CSRF、验证码等机制不保证可用。

网页登录与验证
1. 点「打开登录页」，默认打开领取接口的同源首页，在应用内 WebView 完成登录。
2. Cookie 必须对领取接口域名、路径和 HTTPS 有效；其他网站的 Cookie 不会用来调用此接口。
3. 点「我已完成登录」，应用先加密保存 Cookie，再立即调用一次领取接口验证。这可能就是今天的领取。
4. HTTP 2xx 只表示请求被接受，不保证业务到账。应用显示站点返回原文，请自行核对积分/额度。
5. 401/403 提示未登录或凭据无效；其他 HTTP 错误显示网站信息。网络失败会保留凭据并提示待验证。
6. 点击编辑并保存配置不会调用领取接口；显式「重新登录 / 验证」可能立即领取。更换接口域名后须重新登录，旧 Cookie 不会发送到新域名。

每天签到
- 点击首页圆形「每日签到」按钮，即可为已启用账号执行任务。运行中可切换到其他应用，请勿强制停止本应用。
- 进度与结果显示在首页和通知中；点「每日签到记录」查看每个账号的成功、失败或未确认结果。
- 单账号失败不影响其他账号。登录态失效时，需要到设置页重新登录对应账号。
- 部分已适配站点支持先查询状态再领取、领取后回读确认；自定义站点只显示接口原文，不猜测业务字段。
- POST 不做自动网络重放。自定义 POST 超时或断连后记「结果未确认，当天不再重试」；再次点击、重开页面或进程中断都不绕过此保护。
- 自定义 GET 瞬态网络异常应用层最多退避 600ms 后重试一次；HTTP 错误（含 429/401/403）不重试。
- 不要通过删除再添加绕过 POST 保护，应先到网站确认结果，避免重复领取。

余额与积分显示
- 只对已有只读余额能力的适配平台查询余额/积分，设置页可见时每站点至少间隔 30 秒。
- 查询失败保留旧值并标注失败，不自动领取、不使原本可用的账号失效。
- 不具备只读查询能力的账号显示最近确认的积分或领取原文，不把每日新增奖励冒充总余额。
- 自定义站点的领取接口不会用于余额刷新。卡片显示最近一次成功/失败的返回原文和时间。

代理与通知
- 应用使用手机当前网络/代理/VPN，没有内置代理，也不会启动代理软件。
- 按网站登录域名和 API 域名自行配置直连或代理。使用 VPN/TUN 时，需要直连的域名仍应设为 DIRECT。
- 不要把电脑上的本地代理地址填成手机代理；注意应用分流规则不要误排除本应用。
- 建议允许通知，以看到进度、结果及失效提示。Android 13+ 可在设置页「通知设置」申请权限，旧系统或已授权时打开系统通知设置。
- 拒绝通知不阻止任务启动，请回首页查看结果。
- 网络、DNS、节点质量、网站限流、人机验证或授权状态均可能导致失败，不保证永久免登录。

隐私与删除
- 密码、会话 Cookie、访问/刷新令牌、设备密钥等认证字段通过 AndroidKeyStore AES-GCM 加密，密钥不可导出。
- 用户名、显示名称、站点配置、余额缓存和领取记录保存在应用私有目录，不加密。勿填写私密请求体或令牌；站点返回文本也可能含账号信息。
- 没有开发者分析、遥测、广告或崩溃上报服务器。网络请求仅涉及用户使用的网站、登录授权服务和自行填写的接口。
- 删除账号清除对应本机数据，不会注销远端网站账号。某些第三方授权类型的账号删除时会清空本应用 WebView 的全部 Cookie，可能影响其他账号的网页登录。
- 仅申请联网、前台任务与通知权限；不申请短信、联系人、位置或外部存储权限，禁止应用备份。

验证范围
- 手机端 12 个本地测试套件已通过，覆盖网络协议、账号管理、通用配置、余额、登录、可靠性、运行隔离、历史及两类静态接线检查。
- 发布包通过 Android 编译、4 字节对齐及 v2/v3 签名校验；五档橙色「签」图标入包。
- 我已经将 APK 安装到手机，并连接多个网站成功完成签到领取。但我没有测试所有中转站和机型；本地 HTTP 夹具与静态测试也不能替代通知、升级等生命周期的完整真机验证。
- GET 的一次重试是应用层预算；底层 HttpURLConnection 在无响应时可能透明重发，不能保证所有平台请求次数严格相同。
